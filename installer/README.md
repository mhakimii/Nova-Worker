# Nova Installer — راه‌اندازی یک‌باره

این ورکر کار نصب را انجام می‌دهد: کاربر با Cloudflare وارد می‌شود، نشست ۱۰ دقیقه‌ای
می‌گیرد، نام‌ها را انتخاب می‌کند و ورکر پنل روی حساب خودش ساخته می‌شود.

چرا این ورکر لازم است؟ مرورگر اجازه‌ی تماس مستقیم با `api.cloudflare.com` را ندارد
(پاسخ‌ها هدر CORS ندارند)، پس تبادل کد ورود و آپلود اسکریپت باید سمت سرور انجام شود.
توکن دسترسی فقط داخل KV همین ورکر می‌ماند و هرگز به مرورگر برنمی‌گردد.

---

## ۱) ساخت OAuth client

در داشبورد Cloudflare:

1. حساب را انتخاب کن → **Manage Account** → **OAuth clients** → **Create client**
2. مقادیر:

| فیلد | مقدار |
| --- | --- |
| Grant type | `authorization_code` |
| Response type | `code` |
| Token authentication method | `none` (بدون client secret) |
| PKCE | الزامی، `S256` |
| Redirect URL | `https://<آدرس-نصب‌کننده>/callback` |
| Scopes | `Workers Scripts: Edit`، `Workers KV Storage: Edit`، `Account Settings: Read` |

3. **Client ID** را بردار. Secret لازم نیست — چون از PKCE استفاده می‌کنیم.

> **دام برای استفاده‌ی عمومی:** کلاینت جدید `private` است و فقط اعضای حساب خودت
> می‌توانند اجازه بدهند. برای اینکه **هر کسی** بتواند نصب کند باید کلاینت را
> `public` کنی و کلودفلر برای این کار تأیید مالکیت دامنه با رکورد **TXT** می‌خواهد.
> `*.github.io` دامنه‌ی تو نیست، پس بدون یک دامنه‌ی شخصی این ممکن نیست.
> تا آن زمان نصب برای حساب خودت کار می‌کند.

---

## ۲) دیپلوی نصب‌کننده

پیش‌نیاز: دو Secret در ریپو → `CLOUDFLARE_API_TOKEN` و `CLOUDFLARE_ACCOUNT_ID`.
همان توکنی که دسترسی `Workers Scripts: Edit` و `Workers KV Storage: Edit` دارد.

اکشن **deploy-installer** را اجرا کن و این سه مقدار را بده:

| ورودی | نمونه |
| --- | --- |
| `client_id` | از مرحله‌ی ۱ |
| `install_origin` | `https://mhakimii.github.io` |
| `worker_name` | `nova-installer` |

اکشن خودش این کارها را می‌کند:

1. `_worker.js` را باندل می‌کند و به‌عنوان متن داخل نصب‌کننده می‌گذارد،
2. فضای KV برای نشست‌ها می‌سازد (`nova-installer-sessions`)،
3. نصب‌کننده را منتشر می‌کند،
4. آدرس نهایی و `callback` را در Summary می‌نویسد.

---

## ۳) وصل‌کردن صفحه

آدرس نصب‌کننده را در یکی از این دو جا بگذار:

- در `install/index.html` مقدار `DEFAULT_INSTALLER` را پر کن (برای همه‌ی بازدیدکننده‌ها)، یا
- هر کاربر خودش در بخش «آدرس سرور نصب» وارد کند (در مرورگر ذخیره می‌شود).

---

## ۴) تست

```bash
curl -s https://<آدرس>/health
# {"ok":true,"configured":true,"callback":"https://<آدرس>/callback","origins":["https://mhakimii.github.io"],...}
```

سپس صفحه‌ی نصب را باز کن: دکمه‌ی «ورود موقت به کلودفلر» → تأیید دسترسی‌ها →
بازگشت خودکار به صفحه با شمارش معکوس ۱۰ دقیقه.

---

## متغیرها

| نام | توضیح |
| --- | --- |
| `OAUTH_CLIENT_ID` | شناسه‌ی عمومی OAuth client. راز نیست. |
| `INSTALL_ORIGIN` | مبدأهای مجاز صفحه، با کاما جدا می‌شوند. |
| `OAUTH_SCOPE` | اختیاری؛ اگر خالی باشد همان scopeهای کلاینت درخواست می‌شود. |
| `COMPATIBILITY_DATE` | تاریخ سازگاری ورکری که نصب می‌شود. |

## امنیت

- نشست با شناسه‌ی تصادفی ۲۵۶ بیتی و TTL ۶۰۰ ثانیه در KV نگه داشته می‌شود.
- هر نشست فقط از همان مبدأیی قابل استفاده است که با آن ساخته شده.
- پاسخ‌ها `Cache-Control: no-store` دارند و توکن هرگز در آن‌ها نیست.
- ورودی‌ها (نام ورکر، نام KV، رمز و شناسه‌ی حساب) سمت سرور اعتبارسنجی می‌شوند.
- بعد از نصب موفق، نشست فوراً حذف می‌شود.
